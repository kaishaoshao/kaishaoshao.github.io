# Codex 文档维护约定

本文件适用于 `docs/codex/` 及其子目录。

## 按主题组织，原地更新

- 先阅读本目录的 `README.md`，定位已有主题。
- 同一主题持续更新现有文件。不要为每次修改新建带日期、`v2`、`v3`、`final` 等后缀的文档、任务表或备份目录。
- 使用 Git 提交和历史追踪变更。新增独立主题时才新增主题目录，并同步目录索引。

## Triton Coral 的固定文件

- `triton-coral/plan.md`：第一次运行、逐阶段练习及实施参考。每课给出源码、命令、观察点和验收信号。
- `triton-coral/tutorial.md`：后端开发实战教程总览与大纲。`triton-coral/tutorials/ch01-skeleton/`：已实现骨架的冒烟与调用链。`triton-coral/tutorials/ch02-scalar-single-core/`：正式选项、标量降低和首个单核 ELF 闭环。
- `triton-coral/plan.json`：结构化计划数据，维护阶段、任务 ID、依赖、交付物、验收与状态。
- `triton-coral/tasks.xlsx`：可筛选、可跟踪的任务表，以及方言、阶段验收和存储契约。
- `triton-coral/examples/`：固定的语法样例、输入及独立参考、前端检查、阶段执行协议和测试框架自检。教程正文持续更新在 `plan.md`，不另建版本副本。

动手章节先列修改文件和插入点，再给代码、原理、增量编译命令及预期结果。优先在现有后端入口复用仓库已有的 MLIR/LLVM 转换。需要增加源文件时说明它在正式构建中的职责。

源码布局统一见 `triton-coral/plan.md` 的「源码目录与职责」。每个改动批次标明何时建文件、由哪层调用、如何单独验证。S0-03、原生转换和正式编译接入各自验收。

修改计划时，按变更范围同步上述文件，保持任务 ID、阶段、依赖和验收标准一致。状态以 `plan.json` 为准；若用户先在 Excel 中修改状态，应先核对并回写数据，不能用旧数据覆盖用户进度。

语法或测试范围变化时，同时核对 `plan.json` 的 `syntax_stages` 与 `examples/suite.py` 汇总的用例 ID。kernel 按首次引入的阶段放在 `examples/kernels/`，各阶段数据、参考值及负例放在 `examples/stage_cases/`。跨阶段共享同一 kernel。每个语法增量包含真实 Triton 源程序、独立参考、边界/负例设计、对应 lowering 与方言职责。测试框架自检和仅 TTIR 验证不得计作 Coral 执行通过；缺少真实适配器或证据应明确失败。类型扩展任务 S9-03 在 G5 后可独立推进，不以多核/DMA/Zvt/双缓冲为技术前置。

维护 `syntax_stages[].lesson_entry` 的开课命令、`tutorial_checkpoints` 的小阶段目标及测试和 `standard_test_gates` 的阶段出口。小阶段对应稳定任务 ID，区分源码检查、主机自检、设备用例及待补测试。S1/S2 用标准源程序做 AOT，S3 后累计验证 `kernel[grid](...)`。能从源码生成的 IR 用 `examples/lit` 核对。非法 IR 和内部边界用 verifier fixture，ABI 和运行行为用断言核验。

任务要求、阶段和语法白名单统一维护在 `plan.json`，再同步正文和任务表，运行 `examples/check_plan.py --workbook` 防止漂移。测试协议2按逻辑访存及数据版本检查依赖；已验收的可选能力按执行模式登记并进入累计回归。ABI v3 的参考 codec 不代表固件已实现，必须由 S3-02 完成双端解析与真实六参数验收。

## 保留进度和证据

- 保留既有任务 ID、状态、完成证据和有意义的用户修改，不因重新生成而全部重置。
- 新增任务使用新的唯一 ID。任务范围变化时明确说明需要复核的内容。
- 区分计划、静态检查、构建成功和真实执行通过。不能把占位 ELF、手写固件的已有结果或模型规划写成 Triton 生成代码已经通过。
- 日期使用 `Asia/Shanghai`。文件名保持稳定，更新日期写入正文或结构化字段。

## 修改和提交检查

- 修改前检查 Git 状态及适用的仓库说明，仅提交本次相关变更。
- 检查本地相对链接、JSON 语法、任务 ID 唯一性和依赖无环；修改任务顺序时核对阶段出口。
- 当前路线中，首个 AOT 单核闭环不得新增 TTS、Linalg、RVV、DMA、多核调度或自定义方言作为必要前置。
- 修改 Excel 时保留表格、筛选、冻结窗格、公式和状态验证，并核对内容及显示效果。
- 文档维护不夹带生成后的博客 HTML、带哈希的 CSS/JS、临时图片、缓存、调试日志或历史版本副本。
