# Codex 文档维护约定

本文件适用于 `docs/codex/` 及其子目录。

## 按主题组织，原地更新

- 先阅读本目录的 `README.md`，定位已有主题。
- 同一主题持续更新现有文件。不要为每次修改新建带日期、`v2`、`v3`、`final` 等后缀的文档、任务表或备份目录。
- 使用 Git 提交和历史追踪变更。新增独立主题时才新增主题目录，并同步目录索引。

## Triton Coral 的固定文件

- `triton-coral/plan.md`：实施顺序、设计说明、任务与验收标准。
- `triton-coral/plan.json`：结构化计划数据，维护阶段、任务 ID、依赖、交付物、验收与状态。
- `triton-coral/tasks.xlsx`：可筛选、可跟踪的任务表，以及方言、阶段验收和存储契约。
- `triton-coral/examples/`：固定的语法样例、输入及独立参考、前端检查、阶段执行协议和测试框架自检。教程正文持续更新在 `plan.md`，不另建版本副本。

修改计划时，按变更范围同步上述文件，保持任务 ID、阶段、依赖和验收标准一致。状态以 `plan.json` 为准；若用户先在 Excel 中修改状态，应先核对并回写数据，不能用旧数据覆盖用户进度。

语法或测试范围变化时，同时核对 `plan.json` 的 `syntax_stages` 与 `examples/suite.py` 的用例 ID。每个语法增量包含真实 Triton 源程序、独立参考、边界/负例设计、对应 lowering 与方言职责。测试框架自检和仅 TTIR 验证不得计作 Coral 执行通过；缺少真实适配器或证据应明确失败。类型扩展任务 S9-03 在 G5 后可独立推进，不以多核/DMA/Zvt/双缓冲为技术前置。

## 保留进度和证据

- 保留既有任务 ID、状态、完成证据和有意义的用户修改，不因重新生成而全部重置。
- 新增任务使用新的唯一 ID。任务范围变化时明确说明需要复核的内容。
- 区分计划、静态检查、构建成功和真实执行通过。不能把占位 ELF、手写固件的已有结果或模型规划写成 Triton 生成代码已经通过。
- 日期使用 `Asia/Shanghai`。文件名保持稳定，更新日期写入正文或结构化字段。

## 修改和提交检查

- 修改前检查 Git 状态及适用的仓库说明，仅提交本次相关变更。
- 检查本地相对链接、JSON 语法、任务 ID 唯一性和依赖无环；修改任务顺序时核对阶段出口。
- 当前路线中，首个 AOT 单核闭环不得新增 TTS、Linalg、RVV、DMA、多核调度或自定义方言作为必要前置。
- 修改 Excel 时保留表格、筛选、冻结窗格、公式和状态验证，并核对内容及显示效果。
- 文档维护不夹带生成后的博客 HTML、带哈希的 CSS/JS、临时图片、缓存、调试日志或历史版本副本。
